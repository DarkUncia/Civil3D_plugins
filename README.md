# Civil3D Plugins & BIM Utilities

Набор автоматизированных инструментов и плагинов для среды **Autodesk AutoCAD / Civil 3D**, написанный на C# .NET. Плагины предназначены для аудита структуры чертежей, полуавтоматической верификации геометрии с генерацией COGO-точек, а также для высокоточного экспорта систем координат для последующей BIM-координации (Revit, Dynamo, Navisworks).

---

## 🚀 Основной функционал и команды

### 1. Модуль аудита и экспорта данных геометрии (`C3D_ExportClasses`)
Предназначен для быстрого тестирования окружения и глубокого анализа структуры слоев элементов.

*   **`C3D_ExportData`** — базовая проверочная команда. Генерирует текстовый отчет `C3D_Report.txt` на Рабочем столе пользователя, фиксируя имя активного чертежа и время теста. Используется для верификации корректности загрузки плагина и прав доступа.
*   **`C3D_AnalyzeLayers`** — инструмент детального аудита чертежа. Позволяет выбрать рамкой любые объекты, анализирует их тип, уникальный `Handle`, слой и контейнер-владелец (`BlockTableRecord`, пространство модели/листа). Выгружает структурированную таблицу `C3D_Deep_Analysis.txt` на Рабочий стол.

### 2. Модуль верификации отметок и создания COGO-точек (`CogoFromGeometryCommands`)
Автоматизирует рутинный процесс создания COGO-точек Civil 3D на основе плоских или объемных объектов чертежа.

*   **`CreateCogoSmartVerify`** — интеллектуальный парсер геометрии. 
    *   **Окружности (CIRCLE):** Если окружность имеет физическую координату `Z > 0`, плагин считывает её и создает в этой точке `CogoPoint` с описанием `Circle_GeometricZ`.
    *   **Штриховки (HATCH):** Если выбрана плоская штриховка, плагин сканирует пространство в радиусе 1 метра от её центра, находит текстовые элементы (`TEXT / MTEXT`), очищает их регулярными выражениями от служебных тегов форматирования и парсит числовое значение (высоту). Штриховке присваивается эта отметка, и создается COGO-точка с описанием `Hatch_TextZ`.
    *   **Контроль дубликатов:** Перед созданием точки плагин проверяет существующую базу чертежа в координатах XY. Старые дубликаты автоматически перезаписываются.
    *   **Фильтрация ошибок:** Объекты, у которых не удалось определить высотную отметку (или она равна 0), автоматически переносятся на сервисный слой `_АНАЛИЗ_ОШИБОК` и окрашиваются в красный цвет для ручного контроля инженером.

### 3. Модуль координации и выгрузки XML (`CoordinateExporter`)
Обеспечивает точную передачу локальных систем координат проекта в стороннее BIM-ПО.

*   **`ExportProjectCoordinates`** — выгрузка параметров посадки зданий.
    *   Пользователь выбирает папку для сохранения через стандартный диалог Windows.
    *   Плагин фильтрует выборку, оставляя на чертеже только специфичные блоки с именем `КЛЕН_Базовая точка проекта`.
    *   Из блока считывается атрибут `НОМЕР_ДОМА` для формирования безопасного имени файла: `Код проекта_Очередь_{НомерДома}.xml` (с авторазрешением конфликтов одинаковых имен).
    *   В XML-файл записываются координаты вставки блока (`OriginX`, `OriginY` с максимальной точностью `G17`, `OriginZ` с точностью `F2`) и угол поворота (`RotationInXYPlane` в радианах, `G17`), что соответствует стандартам передачи данных в Dynamo/Revit. По завершении папка экспорта автоматически открывается в Проводнике.

## 🛠 Установка и запуск

### Требования
*   Установленный **Autodesk AutoCAD / Civil 3D** (рекомендуется версия с поддержкой актуального .NET API).
*   Библиотека скомпилирована под архитектуру `x64`.

### Пошаговая инструкция
1. Скомпилируйте проект в Visual Studio (в режиме *Release* или *Debug*).
2. Запустите Civil 3D / AutoCAD и откройте целевой чертеж.
3. Введите в командную строку AutoCAD команду **`NETLOAD`** и нажмите `Enter`.
4. В открывшемся окне выберите скомпилированную библиотеку `Civil3D_plugins.dll`.
5. Запустите любую из команд выше (например, `CreateCogoSmartVerify` или `ExportProjectCoordinates`), введя её название напрямую в консоль чертежа.

# Civil3D_plugins - Синхронизация данных МАФ с Excel

Автоматизированный .NET-плагин для Autodesk Civil 3D (версии 2025/2026), написанный на языке C# (.NET 8.0). Предназначен для пакетного считывания ведомостей малых архитектурных форм (МАФ) из таблиц Excel и автоматического заполнения Наборов характеристик (Property Sets) у соответствующих блоков на чертеже.

Данные подготавливаются в строгом соответствии с требованиями BIM-моделирования для последующего корректного поиска коллизий и координации в **Autodesk Navisworks**.

## 🚀 Основные особенности и архитектура

*   **Изоляция от графического ядра (Zero-Graphics)**: Использование библиотеки `ExcelDataReader` позволяет читать файлы Excel напрямую как чистый бинарный поток байт (`FileStream`). Это полностью исключает классический конфликт версий со шрифтами `SixLabors.Fonts`, жестко зашитыми в ядро Civil 3D, из-за которого падали стандартные библиотеки вроде ClosedXML.
*   **Регистронезависимый поиск**: Плагин автоматически сглаживает различия в регистрах и пробелах при сопоставлении имен блоков на чертеже со строками таблицы.
*   **Полная синхронизация 14 параметров**: Плагин осуществляет заполнение абсолютно всей палитры данных — от артикулов до сложных сквозных BIM-классификаторов.
*   **Динамическая привязка данных**: Если на блоке отсутствует необходимый Property Set `07_МАФ`, плагин автоматически инициализирует и привязывает его к объекту во время выполнения транзакции чертежа.

## 📊 Требования к структуре Excel

Для успешной синхронизации первая строчка (шапка) файла Excel **обязательно должна быть заполнена на латинице** в нижнем регистре. Сопоставление блоков с чертежом происходит по колонке `guid`, значение которой должно соответствовать имени блока в AutoCAD.

Список ожидаемых плагином заголовков колонок:
1.  `guid` — Длинный системный хэш-идентификатор (Имя блока на чертеже)
2.  `id` — Артикул или уникальный код типа МАФ
3.  `manufacturer` — Завод-изготовитель
4.  `name` — Официальное наименование элемента
5.  `dimensions` — Габаритные размеры
6.  `note` — Примечание / Ссылка на каталог элементов
7.  `type` — Тип элемента
8.  `type2` — Подтип элемента
9.  `weight` — Масса элемента
10. `group_id` — Идентификатор группы
11. `version` — Версия элемента
12. `adsk_name` — Наименование по стандарту Autodesk BIM
13. `adsk_set_of_drawings` — Комплект чертежей по стандарту ADSK
14. `acer_codecollision` — Код коллизии ACER
15. `krtrs_code_by_classifier` — Код элемента по классификатору KRTRS

## 🛠️ Настройка проекта в Visual Studio

Чтобы проект корректно собирался под платформу .NET 8.0 и все сторонние runtime-зависимости автоматически падали в выходную папку, в файле конфигурации проекта **`.csproj`** должны быть включены следующие параметры:

```xml
<PropertyGroup>
  <TargetFramework>net8.0-windows</TargetFramework>
  <Platforms>AnyCPU;x64</Platforms>
  <CopyLocalLockFileAssemblies>true</CopyLocalLockFileAssemblies>
</PropertyGroup>

<ItemGroup>
  <PackageReference Include="ExcelDataReader" Version="3.7.0" />
</ItemGroup>
```

## 💻 Инструкция по запуску в Civil 3D

1.  Скомпилируйте проект в Visual Studio под платформу **`x64`** в режиме `Debug` или `Release`.
2.  Откройте Civil 3D и необходимый чертеж.
3.  Убедитесь, что в чертеже через Диспетчер стилей создан Набор характеристик с именем **`07_МАФ`**, содержащий соответствующие свойства (регистр имен свойств внутри AutoCAD не имеет значения, плагин обработает их автоматически).
4.  Введите в консоли AutoCAD команду **`NETLOAD`**.
5.  Перейдите в папку сборки `bin\x64\Debug\net8.0-windows\` и загрузите сначала зависимость **`ExcelDataReader.dll`**, а затем сам плагин **`Civil3D_plugins.dll`**.
6.  Введите в консоли команду **`TEST_FILL_MAF`**.
7.  В открывшемся системном окне Windows выберите подготовленный Excel-файл.
8.  Дождитесь сообщения об успешном завершении синхронизации. Палитра свойств блоков обновится на лету.

## 🔍 Решение возможных проблем (Troubleshooting)

*   **Ошибка `No data is available for encoding 1252`**: По умолчанию .NET 8 не содержит старых кодировок Windows. Плагин решает эту проблему принудительным вызовом `System.Text.Encoding.RegisterProvider` прямо внутри тела команды. Если ошибка сохраняется, убедитесь, что библиотека `System.Text.CodePages` присутствует в скомпилированной папке.
*   **Блоки не обновляются (Обновлено блоков: 0)**: Проверьте колонку `guid` в Excel. Текст в ней должен символ-в-символ совпадать с именем блока на чертеже (включая точки, дефисы и спецсимволы).
*   **Конфликт версий `WindowsBase` при сборке**: В окне предупреждений Visual Studio может появляться сообщение о конфликте версий `WindowsBase.dll`. Это стандартное поведение при работе с API Civil 3D 2025/2026, на успешную компиляцию проекта и работу плагина оно влияния не оказывает.
